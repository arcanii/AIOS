## The procedure (summary -- verify against NEXT_20260411h.md)
1. **mbedTLS source:** v3.6.3 LTS at `~/Desktop/github_repos/mbedtls`. **Verify the
   version is 3.6.3** and the AIOS custom config is applied to
   `include/mbedtls/mbedtls_config.h` (re-apply if the source was re-cloned):
   - DISABLE: `MBEDTLS_FS_IO`, `MBEDTLS_NET_C`, `MBEDTLS_TIMING_C`, `MBEDTLS_AESNI_C`,
     `MBEDTLS_PADLOCK_C`, `MBEDTLS_AESCE_C`, `MBEDTLS_PSA_ITS_FILE_C`,
     `MBEDTLS_PSA_CRYPTO_STORAGE_C`.
   - ENABLE: `MBEDTLS_NO_PLATFORM_ENTROPY`, `MBEDTLS_ENTROPY_HARDWARE_ALT`.
2. **The arm_neon.h gap (already solved):** aios-cc uses `-nostdinc`, which strips the
   GCC intrinsics header `arm_neon.h` that mbedTLS `common.h` includes. Fix:
   `-isystem "$(aarch64-linux-gnu-gcc -print-file-name=include)"`. (I re-confirmed this
   gap on 2026-06-06; it is exactly the documented fix.)
3. **Build `build-04/libmbedcrypto.a`** -- compile the ~81 needed `mbedtls/library/*.c`
   with aios-cc (`-DMBEDTLS_ALLOW_PRIVATE_ACCESS`, the `-isystem` fix, the mbedtls
   include path), then `ar rcs`. Expected: ~81 objects, ~1,181 KB, 815 API symbols,
   ~2s. Use the exact command in NEXT_20260411h.md (lines ~73-87). Smoke: a tiny
   `test_mbedtls` (AES init + SHA-256 + CTR-DRBG seed) should link + PASS.
4. **Relink sshd** -- `aios-cc src/ssh/*.c ... build-04/libmbedcrypto.a -o
   build-04/sbase/sshd` (NEXT_20260412a.md). Then ADD sshd to `scripts/build_apps.py`
   (its apps list) so a clean build keeps it -- same gap psutil/nslookup had.
5. **Deploy + test (no reflash):** push sshd over netconsole
   (`pi_filexfer.py push build-04/sbase/sshd /bin/sshd 192.168.0.8`), run it on the Pi,
   then from the host: `ssh -p 2222 -o StrictHostKeyChecking=no root@192.168.0.8`
   (password `root`). Or QEMU with `hostfwd=tcp::2222-:2222`. Verify: version exchange
   -> KEXINIT -> key exchange -> password auth -> interactive shell (the v0.4.84 state).

## What the SSH server uses (so the config is right)
- mbedTLS APIs (from `src/ssh/`): `aes.h`, `bignum.h`, `ctr_drbg.h`, `ecdsa.h`,
  `ecp.h`, `entropy.h` -> AES-CTR, MPI, CTR-DRBG, ECDSA P-256, x25519 ECDH, SHA-256/512.
- **Entropy:** `src/ssh/aios_entropy.c` implements `mbedtls_hardware_poll` by reading
  `/dev/urandom` (AIOS ChaCha20 CSPRNG via crypto_server). Already wired -- no work.
- **Files:** `sshd_main.c` (listen/accept on 2222), `ssh_transport.c` (framing),
  `ssh_kex.c` (key exchange), `ssh_crypto.c` (mbedTLS wrappers), `ssh_encrypt.c`
  (AES-256-CTR + HMAC), `ssh_auth.c` (password via auth_server), `ssh_channel.c`
  (session channel + shell spawn), `aios_entropy.c`, `ssh_session.h`.
