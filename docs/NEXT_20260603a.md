## TL;DR

* `cat /etc/passwd | wc -l` and `ls /bin | wc -l` return 0 (reader gets EOF);
  `seq N | wc -l` and `echo x | wc -c` work. DETERMINISTIC on BOTH QEMU SMP=4 and
  the single-core RPi4 (NOT intermittent, NOT SMP-specific). The discriminator is the
  WRITER: filesystem-reading forked writers (cat, ls) fault on their demand-BSS and die
  before writing; compute-only writers (seq) and builtins (echo) do not.
* The earlier v0.4.139 "580 pipes / 0 wedge" verification used `echo | wc` (a builtin
  writer, no fork) so it never exercised this. cat/ls were always broken on the Pi.
* Layer 1 (FIXED v0.4.140): bss_reservation was a dangling pointer (UAF). Fixed by
  storing the reservation by value in a per-proc static array.
* Layer 2 (OPEN): even with a correct reservation, the page-table metadata reads
  "not reserved" at fault for the forked-then-PIPE_EXEC path. Deep libsel4utils issue.

## The deterministic, hardware-free repro

  --kernel build-04/images/aios_root-image-arm-qemu-arm-virt \

## Layer 1 -- FIXED in v0.4.140 (use-after-free of bss_reservation)

Mechanism: demand-BSS setup (exec_server.c, pipe_server.c PIPE_EXEC) called
`vspace_reserve_range_at`, which malloc-s a `sel4utils_res_t`, and stored that raw
pointer in `active_proc_t.bss_reservation`. libsel4utils frees/recycles that struct
(COW churn + proc teardown), so the stored pointer dangled and at fault described an
unrelated range. A pointer-identity probe proved it: the SAME struct address was
reserved as the 1580-page BSS, then re-used for a 17-page reservation; at fault the
check_reservation BOUNDS test failed (bounds=0).

Fix (src/servers/pipe_server.c + exec_server.c): store the reservation BY VALUE in a
shared per-proc static array `sel4utils_res_t aios_bss_res[MAX_ACTIVE_PROCS]` and fill
it via `sel4utils_reserve_range_at_no_alloc` (sets malloced=0, so libsel4utils never
frees it -> cannot dangle). Verified `sel4utils_free_reservation` skips malloced=0
entries (vspace.c:661). NO root_shared.h change (BSS-shift-safe, per the had_child
precedent). Result: bounds 0 -> 1, confirmed on QEMU and on the reflashed Pi.

## Layer 2 -- OPEN (libsel4utils metadata-tree node not seen at fault)

With layer 1 fixed, the probe shows bounds=1 meta=0: the reservation struct is correct,
but `is_reserved_range` (the page-table metadata walk) returns 0 for the faulting page.

A vspace-tagged mark/clear trace (watches in reserve_entries_bottom / clear_entries_bottom
on vaddr 0x458000) showed the decisive fact: reserve_entries marks 0x458000 RESERVED
immediately before the fault, with NO intervening clear, yet the fault-time walk does not
see it. So the RESERVED mark lands in a bottom-level metadata node that the walk does not
reach -- a freed/realloced bottom node or a stale mid-level pointer.

Why forked-then-PIPE_EXEC and not plain exec: PIPE_EXEC destroys the old (forked) proc
vspace and immediately creates a new one in the SAME active_procs slot
(pipe_server.c:838 destroy -> 859-867 create), recycling libsel4utils metadata-node
memory from the just-freed predecessor. Plain EXEC_RUN has no destroyed in-slot
predecessor and works. This is Agent-2's "bootstrap vspace reuse" open question,
substantiated. The reserve/check walk logic itself (vspace_internal.h reserve_entries_mid
vs is_reserved_or_empty_mid) is internally consistent -- the bug is node lifecycle, not
walk logic.

## Three fix paths for layer 2 (pick in a focused session)

1. SIDESTEP (most promising): at BSS fault, map the frame WITHOUT relying on the
   setup-time reservation -- allocate a frame (vka) and map at the faulting vaddr,
   allocating intermediate page tables as needed, bypassing libsel4utils reservation
   tracking. Robust against both layers. Must confirm the right libsel4utils map API
   (sel4utils_map_page or similar) AND that vspace teardown still frees the pages
   (no leak).
2. libsel4utils node-lifecycle fix: find why the bottom node reserve writes to is not
   the one the fault walk reads after destroy+recreate in the same slot. Deep, vendored.
   Re-add the mark/clear/probe watches (see git history of this session) to trace it;
   add the bottom-node pointer to the watches to confirm node identity.
3. Eager BSS for PIPE_EXEC: skip demand-BSS for forked-then-exec-d procs (keep
   elf_load eager mapping). Simple + correct, but regresses the v0.4.106 memory win
   (~1580 pages/proc -> ~5 concurrent procs max). Last resort.

## Instrumentation technique (for re-tracing layer 2)

The probes used this session (all reverted before banking; reconstruct from git history):

  check_reservation into check_reservation_bounds + is_reserved_range and log
  bounds/meta/res-bounds/vspace.

  start == <watched vaddr>, tagging vspace and only_reserved.

remember adjacent-to-fault events belong to the faulting proc.
