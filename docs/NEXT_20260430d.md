# AIOS Next Steps -- 2026-04-30d

Continuing from **v0.4.105**. Demand-paged BSS implementation.

## Session Result: Demand-Paged BSS Phase 1 -- WORKING

### Goal
Eliminate eager 6MB BSS allocation per process. Each spawned process
should use only the pages it actually touches (~30-100 KB), not the
full 1500+ pages of static `morecore_area`.

### Result
**~10-50x reduction in per-process page count.** Verified empirically:

| Stage | live pages | Programs |
| --- | --- | --- |
| Boot only | 8 | virtio DMA |
| After `ls` | 129 | shell + ls fault-allocated only what was touched |
| After `echo hello` | 168 | +40 pages for echo |
| After `posix_ps` | (similar growth) | per-program incremental |

Previously, each program would consume 1500+ pages just for empty BSS.
Now they consume only what they actually use. This unblocks long
pipelines and multi-process workflows that previously exhausted the
8000-page pool.

### Implementation

Followed the design in `docs/DESIGN_DEMAND_BSS.md` (Approach A:
post-load unmap).

**Per-process state in `active_proc_t`** (`include/aios/root_shared.h`):
```c
uintptr_t bss_lazy_start;    /* page-aligned, inclusive */
uintptr_t bss_lazy_end;      /* page-aligned, exclusive */
void *bss_reservation;       /* opaque reservation_t.res */
```

**ELF load post-processing** (in both `exec_server.c` and
`pipe_server.c` PIPE_EXEC handler):

1. Parse program headers: find LOAD segments where memsz > filesz
2. Pick the largest BSS region (typically the .bss for morecore_area)
3. Round to page boundaries -> [bss_start, bss_end]
4. `vspace_unmap_pages(VSPACE_FREE)` to release the eager allocation
5. `vspace_reserve_range_at()` to keep address range reserved for
   later fault-time mapping
6. Store start/end/reservation in active_proc_t

**Fault handler** (in both exec_thread fault loop and pipe_server
fault dispatch):

1. After receiving a message on fault EP, check label
2. If `seL4_Fault_VMFault` and address in BSS range:
   - Headroom check (`vka_audit_check_headroom(1)`)
   - `vspace_new_pages_at_vaddr` for one page in the BSS reservation
   - `vka_audit_frame(VKA_SUB_OTHER, 1)` for accounting
   - `seL4_Reply` (resumes the faulted thread)
   - Loop back for more faults
3. Otherwise: existing exit-cleanup path

### Coverage

| Spawn path | Implementation |
| --- | --- |
| `EXEC_RUN` (foreground via shell) | exec_thread fault loop |
| `EXEC_RUN_BG` (getty) | NOT applied -- no fault handler available |
| `PIPE_EXEC` (forked-then-execed children) | pipe_server fault dispatch |

EXEC_RUN_BG is intentionally skipped because exec_thread doesn't poll
the BG fault EP after spawn (would deadlock on first BSS fault).
getty is the only EXEC_RUN_BG user, so the page savings here are
small. All shell-spawned commands use PIPE_EXEC, which now does
demand-page BSS.

### Known Limitations

1. **Audit live count grows monotonically.** When a process exits,
   `sel4utils_destroy_process` does free the demand-paged pages via
   `vspace_tear_down`, but our `vka_audit_frame_release()` is not
   called for them. The `live` counter only decrements via the
   explicit `vka_audit_frame_release` API, which we haven't wired
   into tear_down. Cosmetic -- actual reclamation works.

2. **EXEC_RUN_BG (getty) keeps eager BSS.** Future work: have
   exec_thread spawn a per-BG-process fault dispatcher, or mint
   getty's fault EP into pipe_ep so the central dispatcher handles
   it.

3. **Multi-threaded children share the fault EP.** If two threads
   in the same process simultaneously BSS-fault on different pages,
   pipe_server serializes them via Recv. Shouldn't deadlock, but
   throughput is single-threaded.

4. **Forked children before exec.** If a forked child accesses BSS
   *before* calling exec, it inherits parent's BSS mapping (pre-exec)
   and our handler won't be involved. Not an issue in practice
   (musl/glibc post-fork code only calls exec).
