## Session Result: Logging Round 2 + Boot Resilience

### Goal
Continue migrating ad-hoc `printf` calls (Option 1) and add graceful
degradation to the boot path (Option 2). System should never silently
hang on a missing/broken filesystem -- it should log clearly and
present a recovery banner.

### Changes

**Logging migration round 2** (24 printfs across 6 files):

| File | Module | Migrated |
| --- | --- | --- |
| `aios_root.c` | `root` | 8 (UART map, IRQ bind, idle) |
| `plat/qemu-virt/blk_virtio.c` | `blk` | 14 (DMA alloc, slot probe errors) |
| `plat/qemu-virt/net_virtio.c` | `net` | 6 (DMA, IRQ, queue errors) |
| `plat/qemu-virt/display_ramfb.c` | `gpu` | 2 (fw_cfg, DMA timeout) |
| `plat/qemu-virt/plat_virtio_probe.c` | `plat` | 2 (MMIO map errors) |
| `servers/fs_server.c` | `fs` | 1 (default IPC handler) |

LOG_MODULE setup added to: `blk`, `gpu`, `plat`, `fs` modules
(previously only `boot`, `net`, `hw`, `root`, `auth`, `crypto`,
`exec`, `pipe`, `thread`, `disp`).

**Boot resilience** (graceful degradation):

New `boot_fs_init` return value (was void):
- `BOOT_FS_OK` (0): normal boot, all filesystems mounted
- `BOOT_FS_DEGRADED` (1): only `/proc` available (no disk)
- `BOOT_FS_FATAL` (2): block device init failed entirely

`include/aios/root_shared.h`:
- New status codes + `extern int aios_boot_status`
- `boot_fs_init()` signature changed to return int

`src/boot/boot_fs_init.c`:
- Sets `aios_boot_status` based on init outcome
- Even on failure, mounts `/proc` so dmesg-style queries still work
- Returns aios_boot_status

`src/aios_root.c`:
- Logs status transition (DEGRADED/FATAL warnings)

`src/boot/boot_services.c`:
- If `aios_boot_status != OK`, skip getty spawn
- Print clear `AIOS RECOVERY MODE` banner instead
- System remains running; user sees actionable message
