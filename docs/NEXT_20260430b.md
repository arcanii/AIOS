# AIOS Next Steps -- 2026-04-30b

Continuing from **v0.4.102**. VKA observability + memory pressure logging.

## Session Result: VKA Audit Wiring + Memory Pressure

### Goal
Originally proposed "VKA reclamation" -- but the v0.4.95 leak diagnosis
turned out to be wrong. `sel4utils_destroy_process` already fully reclaims
pages via `vspace_tear_down`. The real issue is **eager morecore BSS
mapping**: every spawned process maps 6MB BSS = 1536 pages immediately,
so a 4-process pipeline (shell | A | B | C) needs ~6000 pages and can
exceed the 8000-page pool when combined with boot allocations.

The proper fix (demand-paged morecore via faulting + on-demand frame
allocation) is a substantial v0.5 project. For v0.4.103 we focused on
**observability and graceful failure** so the system can warn when
pressured rather than silently fail.

### Changes

**vka_audit.c**:
- `vka_audit_frame()` now calls `vka_audit_frame_alloc()` per page,
  so `vka_live_frames` actually tracks subsystem-explicit allocations
- New `vka_audit_frame_release(N)` for reap paths
- New `vka_audit_check_headroom(N)`: returns -1 if pool < N free pages
- Memory pressure thresholds:
  - WARN below 1500 free pages
  - CRITICAL below 500 free pages
- Periodic warning every 100 allocations (not on every alloc)

**exec_server.c**:
- Pre-flight headroom check (2000 pages) before ELF load
- Refuses with clear error rather than letting allocation fail late
- Reply -1 to caller so shell can report failure

**procfs.c (/proc/meminfo fix)**:
- Was: `MemTotal: 0 kB` (bug -- divided MB value by 1024 again)
- Now reports: MemTotal, PoolTotal, PoolUsed, PoolFree, PoolPeak
- All in real kB units

**Caveats** (documented in vka_audit.c):
- Live frame count only tracks subsystems that explicitly call
  vka_audit_frame() / vka_audit_untyped()
- Process spawn (sel4utils_elf_load, BSS, stack) is NOT counted
- Useful for: pipe SHM, virtio DMA, network/display buffers
- Not useful for: per-process page count, tear_down accounting

This is intentional -- catching the major subsystem allocations gives
us early warning of pool pressure even if the count is incomplete.

## Next Session Priorities

### Priority 1: Demand-paged morecore (real VKA fix)
- Stop pre-mapping BSS pages at ELF load
- Catch VM faults on morecore range
- Allocate frames on demand
- Result: small processes (ls, cat) use ~10 pages instead of ~1500
- 4-process pipelines fit easily in pool
- This is the proper fix for the observed memory pressure

### Priority 2: Per-server health probes
- Periodic ping to fs/exec/pipe/net servers
- Auto-restart on death detection
- Distinguishes "frozen" from "broken"
