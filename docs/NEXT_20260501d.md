# AIOS Next Steps -- 2026-05-01d

## TCC self-host: pre-linked libc blob (Approach 3 from NEXT_20260501a.md)

### Status: working

The on-AIOS tcc now links programs that #include <stdio.h> and call
printf, malloc, exit, etc. The libc.a archive parser issue from
v0.4.108 is bypassed by pre-linking everything into a single
relocatable .o that is wrapped as a one-member archive.

### Mechanism

1. `src/lib/aios_tcc_anchor.c` -- references the libc + AIOS runtime
   symbols a typical user program needs (~120 entries: stdio,
   stdlib, string, unistd, fcntl, time, ctype, errno). Each
   reference forces ld to pull the providing .o (and its transitive
   deps) into the blob during -r.
   Also defines weak fallbacks for `__executable_start` (normally a
   linker-script symbol GNU ld auto-creates and TCC does not) and
   `fsl_avic_ptr` (a freescale driver pointer never assigned on
   qemu-arm-virt).

2. `scripts/build_tcc_libc_blob.py` -- compiles the anchor with the
   musl headers, then runs `aarch64-linux-gnu-ld -r` over the same
   archive list aios-cc uses (sel4runtime, libsel4, libsel4*, libaios_posix,
   libplatsupport, libfdt, libelf, libcpio, libutils, musl libc, libgcc/libgcc_eh).
   Output: `build-04/libaios_tcc.o` (~613 KB, 797 defined T symbols,
   8 expected undefined symbols that get resolved by tcc's
   section-anchor generation at user link time).

3. After the link, `objcopy --localize-symbol` runs on three names:
   * `_init` and `_fini` -- sel4runtime crti.S contributes them, but
     the system /usr/lib/crti.o (which tcc adds to every link)
     defines them too. Localizing in the blob avoids the conflict.
   * `__sel4_start_c` -- both sel4runtime crt1.c and aios_crt1.S
     define it. aios_crt1.S uses bl-only relocations that tcc
     handles cleanly, so we keep it in the user link and localize
     the blob's version.

4. `--wrap=main` and the pthread/pwd/grp `--wrap` directives from
   aios-cc are intentionally NOT passed to ld -r. Setting
   `--wrap=main` rewrites every reference to main inside the blob
   (notably `__aios_entry -> main`) into `__wrap_main`, which then
   tail-calls a weak `__real_main`. User programs that link against
   the blob without re-specifying the wrap leave `__real_main` as
   NULL, and the program crashes silently before printing anything.
   The wraps are only meaningful at the final user link, not during
   -r.

5. `scripts/build_tcc_sdk.py` -- wraps the blob in a single-member
   `/usr/lib/libc.a` so tcc's default `-lc` resolves to it. The on-
   AIOS tcc archive scanner handles a one-member archive without
   issue. The original 1418-member augmented libc.a is still
   available as `/usr/lib/libc_full.a` for host tooling that can
   parse it. The blob is also installed standalone as
   `/usr/lib/libaios_tcc.o`.

6. `scripts/build_apps.py` runs `build_tcc_libc_blob.py` between
   `build_libaios.py` and `build_tcc_sdk.py` so the SDK staging
   always picks up a fresh blob.

7. `scripts/ext2/builder.py:mkfile` now replaces existing entries
   with the same name rather than appending. Without this, the
   rootfs `/usr/lib/libc.a` (a stale committed copy) and the SDK
   staging `/usr/lib/libc.a` (the new blob-wrapped one) both end up
   as separate dir entries, and the on-AIOS tcc picks whichever
   the dir-block scan finds first -- producing a silent shadowing
   bug that was the root cause of "tcc still cannot parse libc.a"
   on the first attempt.

8. Stale committed copies of the SDK contents (`disk/rootfs/usr/lib/*`
   and `disk/rootfs/usr/include/*`) are removed from the repo.
   Source of truth is the SDK staging only.

### Verification

* Host-linked ELF using the blob runs on AIOS and prints from
  printf:
  ```
  Run /root/hello_blob (host-linked ELF using libaios_tcc.o):
  hello from blob test
    i=0
    i=1
    i=2
  exit=42
  ```
* On-AIOS `tcc -o /tmp/hi /tmp/hi.c` (where /tmp/hi.c is the
  pre-existing printf hello in the rootfs) compiles and links
  cleanly via the blob-wrapped libc.a, producing a runnable AIOS
  ELF.

### Caveats

1. **Demand-paged BSS intermittent fault.** Under tcc's memory
   pressure the lazy-BSS handler in `pipe_server.c` sometimes
   trips on a vaddr that is in `[bss_lazy_start, bss_lazy_end)` but
   `vspace_new_pages_at_vaddr` returns -1 ("Range for vaddr ... not
   reserved"). The process then loops or hangs. This is unrelated
   to the blob -- it is the v0.4.106-107 BSS handler interacting
   poorly with tcc's larger working set. Roughly 1 in 3 boots
   reproduces the issue. When it does not trigger, the test passes.

2. **filehits.h tuning.** v0.4.116 ships with `FILEHITS_MAX=96,
   FILEHITS_PATH_MAX=80` precisely because larger values push the
   `_filehits` static array onto a different page during early boot
   and `plat_blk_init` reads junk for the virtio block-device count.
   The bug is documented in the file. If a future change needs
   bigger buffers, fix the underlying virtio-blk warmup race first.

3. **Anchor coverage.** `aios_tcc_anchor.c` references ~120 libc
   functions. If a user program calls something not on the list
   (regex, getopt_long, locale, dlopen-style code), the link will
   report it undefined. Add the symbol to the anchor and rebuild
   the blob.
