# AIOS Next Steps -- 2026-05-01a

## TCC Self-Host: Basic Working, libc Linking Blocked

### What works (v0.4.108)

```
echo "int main(){return 42;}" > /tmp/t.c
/tmp/tcc2 -o /tmp/t /tmp/t.c
/tmp/t; echo $?       -> 42
```

Programs that do not call libc functions compile and link cleanly via
the on-disk tcc2 binary. The output is a real AIOS ELF that runs and
returns the expected exit code.

### What does not work

Programs that #include <stdio.h> and call printf() trigger a TCC
linker failure. Two distinct issues:

1. **`/usr/lib/libc.a: error: invalid archive`**
   - libc.a has 1417 archive members with 10+ duplicate names
     (bootinfo, bootstrap, clone, crt0, device, elf, fdt, io, mapping,
     serial, etc.)
   - TCC's archive parser scans members linearly and trips over
     duplicates (documented in v0.4.95 docs/NEXT_20260415b.md)
   - This is GNU ar producing System V multi-archive format that TCC
     does not handle the same way GNU ld does

2. **libc_min.a (177 unique members) parser also fails**
   - When invoked as `/tmp/tcc2 -o /tmp/hi /tmp/hi.c /usr/lib/libc_min.a`,
     TCC dumps binary archive contents to stdout and exits without
     producing /tmp/hi
   - The dumped bytes contain readable strings from posix_misc.c
     debug info, suggesting TCC is mis-reading archive headers and
     spewing object content
   - Same archive format magic (`!<arch>`) that GNU ar produces

### Root cause hypothesis

TCC's libtcc.c arch_load_archive() implementation has known issues
with archives larger than a few hundred members or with specific GNU
ar features (extended filename table, BSD vs SysV string table).
This is upstream TCC behavior, not AIOS-specific.

### Possible fixes (future sessions)

1. **Use a TCC-friendly archive packer.** Repack libc.a using a
   custom Python tool that emits a strictly-flat archive with no
   long-filename support and unique member names.

2. **Split libc into many small archives.** Instead of one libc.a,
   produce libc_io.a, libc_str.a, etc. -- each <100 members. Test
   whether TCC scans them correctly.

3. **Static linking via .o files.** Pre-link the relevant musl/AIOS
   objects into a single .o (using `ld -r`) and link that .o into
   programs instead of an archive. Avoids archive scanning entirely.

4. **Patch TCC archive parser.** Find the exact failure point and
   submit upstream. Most direct fix but requires TCC source diving.

5. **Use crt + minimal stub library.** Maintain a hand-curated list
   of <100 essential .o files and pack them into a TCC-friendly
   archive. Trade-off: limits which libc functions work in
   on-AIOS-compiled programs.
