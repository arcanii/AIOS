## TL;DR
The post-GENET network-control goal is DONE and HW-verified on the real RPi4: drive the Pi
over the LAN, reboot it over the network, and it auto-recovers -- no serial after flashing.
netconsole v2 (command-per-connection), a net_server accept-backlog fix, BCM2711 watchdog
reboot, and getty-based auto-start all shipped. One HW-only bug surfaced and was fixed: the
pipe SHM transfer frame had mismatched cacheability (server cacheable / client non-cacheable)
so the Cortex-A72 served stale zeros and netconsole output came back all-NUL -- invisible on
QEMU, only real hardware exposed it. Committed `616aa10` (v0.4.164).

## What shipped (v0.4.163 -> v0.4.164)
- **netconsole v2** (`src/apps/netconsole.c`): rewrite from the v1 interactive `dash -i` relay
  (which never flowed I/O on HW -- no tty/line discipline) to command-per-connection: read a
  socket line, run `dash -c "<line>"` (runs + EXITS -> clean stdout EOF), stream output to the
  socket, loop. O_NONBLOCK poll + per-command timeout/SIGKILL so a stdin-reading command cannot
  wedge the server. Child stdin = a writer-less pipe (NOT /dev/null -- libc-only, lost across
  exec; NOT absent -- would steal the serial console via TTY_READ).
- **net_server accept backlog** (`src/servers/net_server.c`): `NET_ACCEPT` now drains an
  already-ESTABLISHED child (`listen_parent == sid`) before blocking. Fixes the fast-reconnect
  race (the wake-on-handshake only fired if a caller was already blocked) that capped netconsole
  AND sshd at one session. `listen_parent = -1` marks a connection consumed (no new struct field).
- **reboot** (`src/aios_root.c`, `src/boot/boot_device_map.c`, `src/apps/reboot.c`,
  `src/apps/shutdown.c`): BCM2711 watchdog. PM block 0xFE100000 mapped ascending in
  prealloc_rpi4_devices (between vcmbox 0xFE00B and gpio 0xFE200000). aios_system_reboot() arms
  PM_WDOG then PM_RSTC full-reset (PM_PASSWORD 0x5A000000). `reboot` and `shutdown -r` send
  PIPE_SHUTDOWN with a reboot flag in MR0. QEMU has no PM block -> clean-halt fallback.
- **auto-start** (`src/apps/getty.c`): getty forks+execs /bin/netconsole ONCE at startup.
- **pipe SHM cache fix** (`src/servers/pipe_server.c`): map the PIPE_MAP_SHM xfer frame
  non-cacheable in the server to match the client. See "the HW-only bug" below.

## Key lessons (recorded in memory)
- **[[pipe-shm-cache-coherency]] -- the HW-only bug.** Any frame shared across vspaces must use
  IDENTICAL cacheability on every mapping. The pipe SHM xfer page was cacheable in pipe_server,
  non-cacheable in the client -> on the A72 the server's write stayed in D-cache while the client
  read stale zeros from RAM -> netconsole returned output as the right LENGTH but all NUL bytes.
  Shell pipes (cat|wc) dodged it because stdin reads use the MR path (label 62), not SHM.
  **QEMU does not model cache attributes -- a 9/9 QEMU pass did NOT validate it; only HW did.**
- **Do NOT spawn extra services from the boot critical path.** Auto-starting netconsole via
  EXEC_RUN_BG from boot_services.c (before OR after getty, even with a vka settle) reliably
  ABORTED the root server: a second big-morecore ELF load back-to-back with getty's OOMs because
  getty's just-freed frames are not reclaimed yet (allocation-triggered watermark refill), even
  though steady-state free is ~7400 pages. The fix: spawn from a RUNNING, post-settle process
  (getty fork+exec), which uses the normal PIPE_EXEC path that fails gracefully instead of aborting.
- **post-v0.4.143 pipe EOF.** A pipe read EOFs only when the REGISTERED writer (the exec'd dash,
  recorded at PIPE_EXEC) exits -- so netconsole's parent can close all its pipe ends right after
  fork and no-output commands still EOF cleanly. The v1/ssh "defer-close-until-first-byte" dance
  is obsolete. waitpid has no WNOHANG (wait4 ignores options) -> poll with O_NONBLOCK + timeout.
